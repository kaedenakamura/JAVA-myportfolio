📋 機能要件・実装詳細
ロードマップの要件定義に厳密に準拠し、初学者が判断しやすいインフラの課題まで論理的に解決して実装しています。

1.権限（ロール）に紐づいたダッシュボード制御
共通機能：登録アカウントでのログイン（バリデーション/エラーメッセージ表示）、ログアウト。
管理者機能:年間・月間の「いいね」ランキング表示、アカウントの閲覧・ステータス変更（有効/有効）、お問い合わせの管理およびステータス（未対応/対応中/対応済み）の更新。
一般ユーザー機能：自身の年間・月間合計の「いいね」獲得権利表示、プロフィール設定（メアド・パスワード・名前の変更）。
2. 実務を見据えたデータ構造と「論理削除」の徹底
すべてのテーブルに関しては、実務のデータ運用で標準となる「論理削除（Logical Delete）」を一貫して実装しています。

全エンティティにcreated_at（作成日）、、updated_at（更新日）のdeleted_at（削除日）カラムを配置。
DELETE文を走らず、フラグやタイムスタンプの制御によってデータを安全に保護する設計を徹底しました。
3. 三項演算子による「ポータブルなDB接続（環境変数）」の設計
ローカル開発環境（Eclipse/localhost）と本番のコンテナ環境（Docker/db）で、「ソースコードを1行も書き換えることなく自動で接続先が切り替わる」柔軟な設計（System.getenv()を用いた三項演算子による自信値へのフォールバック）を採用しています。

4. Docker Composeによるコンテナ間依存関係の制御
MySQLが完全に起動し、ヘルスチェック（mysqladmin ping）がhealthyなるまでJavaアプリ（Tomcat）の起動を安全に待機させる（depends_on.condition）制御を記述します。本番環境で発生しやすいコンテナ間の起動タイミングのズレによるネットワークエラーを根本的に解決しています。
